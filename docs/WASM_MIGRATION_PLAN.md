# แผนการย้ายระบบประมวลผลวิดีโอไปยังเบราว์เซอร์ (WebAssembly - ffmpeg.wasm)

## 1. บทวิเคราะห์สถาปัตยกรรม (Architecture Analysis)

การย้ายการประมวลผล (FFmpeg) จาก Server (Render) มาไว้ที่หน้าเว็บ (Client-side) ด้วย `ffmpeg.wasm` เป็นการปรับเปลี่ยนที่ชาญฉลาดสำหรับระบบฟรี

### 🟢 ข้อดี (Pros)
* **ความเร็วแสง (Zero Upload/Download):** ไม่ต้องเสียเวลาอัปโหลดไฟล์วิดีโอขึ้นเซิร์ฟเวอร์และดาวน์โหลดกลับ
* **ลดภาระเซิร์ฟเวอร์ 100% (Zero Server Cost):** Backend จะกลายเป็นเพียง API ธรรมดา ปัญหา Server ล่มหรือค้างเพราะ CPU ไม่พอจะหมดไป
* **ความเป็นส่วนตัวสูงสุด (Privacy):** ไฟล์วิดีโอของลูกค้าจะไม่ออกจากเครื่องของพวกเขาเลย ปลอดภัย 100%

### 🔴 ข้อจำกัด (Cons & Risks)
* **Initial Load Time:** ต้องดาวน์โหลด Core ของ `ffmpeg.wasm` (ประมาณ 20-30MB) ในการเปิดเว็บครั้งแรก
* **ข้อจำกัด RAM ของ Browser:** WebAssembly ถูกจำกัดการใช้ RAM ในเบราว์เซอร์ (ปกติไม่เกิน 2-4GB) หากไฟล์ใหญ่เกินไปแท็บจะค้าง (Aw, Snap!)
* **ใช้ทรัพยากรเครื่องลูกค้า:** พัดลมคอมพิวเตอร์จะดัง แบตเตอรี่มือถือจะลดเร็ว และเครื่องอาจร้อนระหว่างการประมวลผล

### 🛡️ กลยุทธ์การป้องกันลูกค้าไม่พอใจ (UX/UI Mitigations)
1. **File Limits (จำกัดขนาด):** ต้องเขียนโค้ดดักจับขนาดไฟล์ เช่น ห้ามเกิน 500MB และความยาวไม่เกิน 10 นาที
2. **Honest Warnings (ป้ายเตือนที่จริงใจ):** แจ้งให้ผู้ใช้ทราบว่าระบบทำงานบนเครื่องของพวกเขา แนะนำให้ใช้บน PC/Mac เพื่อความเสถียร
3. **Progress Indicators (หลอดความคืบหน้า):** ต้องมี Loading UI หรือ Progress Bar (0-100%) ที่ชัดเจน ป้องกันผู้ใช้คิดว่าเว็บค้าง

## 2. ขั้นตอนการลงมือทำอย่างละเอียด (Implementation Steps)

### Step 1: ติดตั้งและตั้งค่าไลบรารี
1. ติดตั้ง `@ffmpeg/ffmpeg` และ `@ffmpeg/util` ในโปรเจกต์ `frontend`
   * `npm install @ffmpeg/ffmpeg @ffmpeg/util`
2. ตั้งค่า COOP/COEP Headers ใน Vite (`vite.config.js`) เพื่ออนุญาตให้ใช้งาน SharedArrayBuffer ซึ่งจำเป็นสำหรับ `ffmpeg.wasm` (Multi-threading)

### Step 2: ปรับปรุง UI หน้าอัปโหลด (UploadZone.jsx)
1. เพิ่มโค้ดตรวจสอบขนาดไฟล์ (เช่น `file.size > 500 * 1024 * 1024`) หากเกินให้แสดง Alert ทันที
2. เพิ่มข้อความแจ้งเตือนด้านล่างพื้นที่อัปโหลด: *"เพื่อความรวดเร็วและเป็นส่วนตัว ระบบจะประมวลผลบนเครื่องของคุณ แนะนำให้ใช้บน PC/Mac"*

### Step 3: ย้ายตรรกะการประมวลผลมาที่ React (App.jsx / VideoProcessor)
1. โหลด FFmpeg Core เมื่อแอปเริ่มต้น หรือโหลดเมื่อผู้ใช้เลือกไฟล์
2. สร้างฟังก์ชันที่ใช้ `ffmpeg.wasm` ในการดึงเสียง (`.wav`) ออกจากวิดีโอ
3. **ทางแยกเรื่อง AI (Silence Detection):**
   * *ตัวเลือก A:* ส่งแค่ไฟล์เสียง `.wav` (ขนาดเล็กกว่าวิดีโอมาก) ไปให้ Backend คำนวณช่วงเงียบ แล้วส่ง Array กลับมา
   * *ตัวเลือก B:* หาไลบรารี Audio Analysis บน Browser (ยากกว่า แต่ลดภาระ Server 100%)
   * *แนะนำ:* ใช้ ตัวเลือก A เพราะการหา Silence ยังทำบน Server ได้เร็วและไฟล์เสียงขนาดเล็ก
4. เมื่อได้ Array ของจุดตัด (Cut Ranges) มาแล้ว ให้ใช้ `ffmpeg.wasm` บน React ทำการ Slicing และ Concatenation (ใช้ตรรกะ FFmpeg Filters ที่เราเพิ่งเขียนไป นำมาแปลงเป็นคำสั่ง WASM)

### Step 4: อัปเดต Progress UI
1. เชื่อมต่อ Event `ffmpeg.on('progress', ...)` เพื่อเอาค่าเปอร์เซ็นต์มาอัปเดต Progress Bar ให้ผู้ใช้เห็นว่าระบบกำลังทำงาน

### Step 5: จัดการการดาวน์โหลด
1. เมื่อประมวลผลเสร็จ `ffmpeg.wasm` จะให้ไฟล์ออกมาเป็น `Blob`
2. สร้าง Object URL จาก `Blob` และสั่งให้เบราว์เซอร์ดาวน์โหลดไฟล์อัตโนมัติ (เหมือนที่ทำในปัจจุบัน) ทันที

### Step 6: เก็บกวาด Backend
1. ลบฟังก์ชันการโหลดวิดีโอใหญ่ๆ อัปโหลด และล้างไฟล์วิดีโอใน `backend/api/routes.py` ออก
2. Backend จะเหลือแค่ Endpoint สำหรับรับไฟล์เสียง `.wav` -> หา Silence -> ส่ง Array กลับ
